## 0. 一句话目标（修订版）

做一个 Edge 插件充当「求职行动端」，与作战台（obs.jobhunt.top）双向打通：
在真实投递 / HR 沟通场景里**低摩擦采集数据**（正在看哪家 JD、投了哪家、HR 回了什么、状态走到哪）、**按需调用站内简历库与 AI** 生成打招呼语与回复语，并把数据沉淀回作战台，让作战台从「记录台」升级为**能积累、能统计、能反哺简历优化的数据闭环**。

## 2. 目标 SMART 化（季度级草案）

- **O（总目标）**：让「投递 → 沟通 → 复盘 → 优化」全程有数据、有统计、有 AI 辅助，把投递→笔试/面试转化率做出可量化提升。
- **KR1 数据完整性**：≥90% 已投递公司的状态在作战台可追踪（插件同步后），状态变更留痕（时间线）。
- **KR2 沟通时效**：HR 消息当天回复；AI 回复语草稿采纳率 ≥70%（用户确认后才发送）。
- **KR3 转化提升**：统计页上线后首月定基线，此后每 4 周漏斗转化率环比不降、目标季内上升。
- **KR4 简历迭代**：每 2 周基于统计数据产出一条简历/来源优化建议并执行（形成循环动作）。

## 3. 分析：关键约束与红线（继承项目哲学，勿破坏）

1. **确认后写入**：插件 AI 产出只是草稿；填充输入框 / 写入数据库必须用户确认（与站内红线一致，也防平台风控）。
2. **账号隔离**：插件用同一 Firebase 账号登录，只读写本人 `states/{uid}`；绝不做任何跨账号能力。
3. **密钥只在服务端**：插件不含任何密钥字面量；AI 走 Cloudflare Worker（或本地代理）+ Firebase ID Token。
4. **只做「用户视角」的采集与辅助**：不自动海投、不自动发送消息、不绕验证码、不高频轮询 —— 降平台风控与合规风险。
5. **数据质量 > 功能数量**：统计与简历优化的价值上限 = 状态数据的完整与及时，故「一键、低摩擦入台」是插件第一价值。
6. **站点是整文档写语义**（`states/{uid}` 整份写 + 防回环）：插件直写需谨慎 —— 建议新增受控写入通道（站点侧轻量入口或插件内「读→改→写 + 冲突兜底」），并把每次变更追加进 `statusHistory`。

## 4. 优化后的目标体系（三层）

- **L1 行动端（Edge 插件）**：在场采集（当前 JD、投递动作、HR 消息、状态变化）+ 即席生成（打招呼 / 回复草稿）+ 一键入台。
- **L2 数据台（网站）**：全量投递与沟通数据 + 状态时间线 + `/stats` 统计页。
- **L3 决策闭环（反哺）**：按来源平台 × 分层 × 岗位 × 简历版本分析转化 → 输出简历/话术/来源建议 → 回流素材库与求职意向 → 更准的下一轮投递。

## 5. 正向循环设计

```
插件采集(看 JD/打招呼/投递/HR 消息) ──▶ 自动/一键入台(真实数据)
        ▲                                          │
优化下一轮投递(简历版本/话术/来源)              状态时间线 + 复盘(面试记录已有)
        ▲                                          │
简历/策略优化建议 ◀─── /stats 统计(漏斗/来源/耗时) ─┘
```
前提：每个环节摩擦最小（插件自动）、数据真实（确认后写入）、复盘及时（现有 `/interviews` 30 分钟记录）。

## 6. 度量口径（统计页 v1）

- 投递全景：总数、按来源平台/分层/岗位分布、周投递节奏 vs 目标；
- 漏斗转化：投递 → 笔试、笔试 → 面试、面试 → Offer、最终 Offer 率；
- 阶段耗时：各状态停留时间（依赖 statusHistory 积累后自动呈现）；
- 沟通效率：打招呼回复率、HR 响应时长、回复语采纳率；
- 对比视图：简历版本 / 来源平台 / 分层 × 邀约率 → 供 L3 优化取数。

## 7. 分阶段目标

- **P0 · 数据通路与统计（已确认先行；先让数据开始积累，价值立即可见）**
  - `Application` 增量：来源平台字段 + JD 摘要 + `statusHistory[]`（顺带完成 roadmap「状态变化时间线」未办项）；
  - 插件 v0.1：同账号登录 → 一键「标记已投 / 改状态」半自动同步（**首平台：Boss直聘/猎聘等直聊场景**，架构平台可扩展，确认后写入）；
  - `/stats` v1：全量公司统计与分析页。
- **P1 · AI 写手**：JD 采集 + 打招呼语生成（简历库 × JD → 草稿）；HR 回复建议（读取会话 → 2–3 版草稿 → 一键填入）。
- **P2 · 简历反哺闭环**：简历版本/来源平台 × 邀约率对照、JD 关键词画像 → 「简历优化建议」清单（素材库迭代引导）。
- **P3 · 扩展与打磨**：更多平台适配、周报自动生成、备份/导入兼容、可选飞书推送（对齐 docs/FEISHU_BOT_PLAN.md）。

**非目标（明确不做）**：自动海投、自动发送消息、爬取平台全量数据、跨账号任何操作。

## 8. 已确认决策（2026 秋招周期）

1. **Q1 主战渠道**：打招呼语与 HR 回复语发生在 **Boss直聘 / 猎聘等招聘 App 直聊**场景 —— 插件主战场为直聊页面（会话采集 + 话术生成 + 状态采集），架构按多平台可扩展设计。
2. **Q2 完善在线简历**：双语义都在范围内 —— ① 用站内简历/求职意向**填充完善平台在线档案**（P2 落地）；② 按具体 JD 生成**简历优化建议**并回流素材库（P2 落地）。
3. **Q3 P0 顺序**：**同步链路 + 统计页先行**（P0）→ AI 写手（P1，适配 Boss直聊）→ 简历反哺闭环（P2）。
